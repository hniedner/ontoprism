# Audit workflow

Adapted from OpenClaw (MIT, see ../LICENSE.md). Use it after the [authoring gate](../SKILL.md#authoring-gate). A
campaign over a whole subsystem also requires [CAMPAIGN.md](../CAMPAIGN.md).

## Junk patterns

Reject new tests that match these patterns unless the [retention bar](#retention-bar) identifies an independent
contract. Audit existing tests that match them:

- Probes without assertions, self-comparisons, identity copiers, or expected values generated by the subject under
  test.
- Copied inventories, manifests or export lists; exact greps of source, imports or strings.
- Tests of private predicates or call shapes that duplicate proof at the boundary; repeated invocations or local
  replays of shared helpers.
- Test-only exports, globals or wrappers, and production paths that only tests call.
- Mocks that implement the asserted behaviour, or that pretend distinct APIs match.
- Fixtures that supply receipts, admission or callback ordering the owner should produce. Persistence asserted against
  a store the path never writes.
- Capability flags asserted instead of the promised delivery or acknowledgement.
- Negative controls that pass on an unrelated guard, or on a rejection that can never be reached.
- Names that promise behaviour the inputs and assertions never exercise.

## Retention bar

Keep independent contracts of these kinds:
- public API, SDK and protocol;
- config, defaults and migration;
- storage;
- security;
- platform;
- generated cross-language output;
- package, release and architecture.

Keep observable ordering and credible regressions.

A source inspection is valid when it is the cheapest independent guard of a user-facing key, byte or path, and it
survives identifier-only refactoring. Static or slow is not a reason to delete. A baseline failure may be a product
bug: reproduce it and repair its owner instead of deleting the test.

A reset hook for process-global state, used by test fixtures, is not junk when the global is real production state
that would otherwise leak between tests. Keep it, name it as test support, and give it no production caller.

## Candidate evidence

Before editing, read in full:
- the test and its production owner;
- the entry point, callers, callees and siblings;
- overlapping proof;
- CI routing and history.

For claims a dependency backs, inspect the dependency's source or types. Read the root and scoped instructions
(CLAUDE.md, AGENTS.md).

Record for each candidate:
- its exact name and location, and the failure it can detect;
- the non-test callers of the production or support seam it covers;
- the stronger owner proof that remains, or why none is needed;
- why it exists (history), and what deleting it unlocks;
- the risk, and the focused command that validates the change.

Missing evidence means no deletion.

Keep discovery read-only and report it before any edits. Prefer a few high-confidence candidates. Parallel discovery
can split the work by independent owners.

When editing:
- delete obsolete seams and dead paths;
- move retained regressions to their owner;
- consolidate generic package and dependency contracts.

Prefer a net reduction in production lines. Never add replacement tests of implementation details, and never turn
uncertainty into cleanup.

## Validation and handoff

Never edit a checkout while a test run is active in it. Run the owner's tests and its siblings' tests. For removed
source greps or plan assertions, exercise the owning executable or its dry run. Run the targeted formatter and
`git diff --check`, then run the project's checks for the changed paths. Inspect `git diff --numstat` and get a final
independent review.

Report:
- causes;
- removed categories and seams;
- retained false positives;
- proof and its cost;
- production lines vs test and support lines;
- PR state;
- follow-ups.

Commit, push or land only when authorised. Refresh from main and rediscover before the next audit batch.
