# Test Audit

Adapted from OpenClaw's test-audit skill (MIT, (c) 2026 OpenClaw Foundation; see LICENSE.md):
https://github.com/openclaw/openclaw/blob/main/.agents/skills/test-audit/SKILL.md.
Project-specific paths and tools were replaced with general wording.

Every new or changed test passes the authoring gate. Audits remove low-value proof in coherent batches, one owner at a
time, and never to meet a deletion count. For a campaign over a whole subsystem, read [CAMPAIGN.md](CAMPAIGN.md) first.

## Authoring gate

Before adding a test, answer:

1. What observable behaviour, invariant or independent contract does it protect?
2. What credible regression makes it fail?
3. Why does existing proof not catch it? Each contract has one primary owner, at the strongest boundary. A test at
   another layer needs a distinct risk of its own, such as transport or lifecycle. Extend the existing tables and shared
   fixtures, and consolidate repeated setup.
4. Does it need an export, flag, wrapper or injection hook that no production code calls? Move the proof to the real
   boundary instead.

A regression test must fail on the pre-fix code for the intended reason and pass after the repair. If that baseline
proof is unavailable, say so. One owner regression covers a bug; do not replay it at every layer the bug crossed. A
refactor that preserves behaviour should not break the test.

## Junk patterns

Reject:
- self-comparisons;
- copied inventories;
- source greps;
- assertions on implementation details or call shapes;
- duplicate contracts;
- test-only seams;
- expected values generated by the subject under test;
- mocks that supply the behaviour being asserted.

Fixtures must not fabricate the owner's receipts or ordering, and must not claim persistence the path never writes.
Negative controls must fail at the intended guard. Test names must match the behaviour actually exercised. When
auditing candidates, use the [full checklist](references/audit.md#junk-patterns).

## Retention bar

Keep independent contracts of these kinds:
- API, SDK and protocol;
- config, defaults and migration;
- storage;
- security and privacy;
- platform and package;
- release and architecture;
- generated output and observable ordering.

A static or slow test is not disposable for that reason. A source inspection must survive identifier-only refactors
and guard an independent user-facing contract. A baseline failure may be a bug to repair, not a test to delete.

## Audit and validation

Before an audit edit, read [candidate evidence and workflow](references/audit.md#candidate-evidence). Inspect the
owners, callers and history in full, and record the proof that remains before deleting anything. Delete obsolete
production seams together with their tests; never optimise for deletion counts.

Then:
- run the project's own test commands for the owner and its siblings, plus the changed checks;
- never edit a checkout while a test run is active in it;
- get an independent review.

Report:
- causes;
- retained contracts;
- proof and its cost;
- production lines vs test lines changed;
- follow-ups.

Commit, push or land only with task authority.
